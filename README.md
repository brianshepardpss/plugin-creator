# Plugin Creator

A lab that builds, publishes and measures Claude plugins at four levels of
abstraction, each aimed at a different customer base:

| Level | What | Plugins | Who it is for |
|---|---|---|---|
| 1 | The plugins | grounded-scala, analyzer-loop, merge-medic, helpdesk, structured-hiring, deal-tender, listing-desk, construction-pm, restaurant-ops, grant-desk | Developers, SaaS users, and industries with no official coverage |
| 2 | A plugin that builds plugins | plugin-creator | Plugin authors |
| 3 | A plugin that runs a portfolio | plugin-studio | Anyone shipping several plugins (starting with us) |
| 4 | Plugins for non-developers, built from their own examples | make-my-plugin + the "built for you" waitlist | Domain experts and small businesses |

Install everything:

```
/plugin marketplace add brianshepardpss/plugin-creator
/plugin install <plugin>@plugin-creator
```

## How the lab works

- `plugins/<slug>/` is the source of truth. Each plugin is published to its
  own repo (`lab/publish.sh <slug>`) so GitHub traffic is measurable per
  plugin; this repo is the marketplace.
- `research/` holds the design brief behind each Level 1 plugin.
- `CONVENTIONS.md` is the rulebook; `python3 lab/check.py` enforces it.
- `lab/studio.json` + Plugin Studio's `collect.py` track traction daily.
- `lab/radar-*.md` ranks the next candidates by measured gap.
- `docs/` is the public catalog and the Level 4 waitlist, generated by
  `python3 lab/build_site.py`.

See `RUNBOOK.md` for the day-to-day commands.
